When a premise changesPROPOSED · DEC-003

Changes to either behavioral model reopen affected comparisons. The earlier model pair and evidence remain historical.

1
Auditor → controller → worker

Authorize model pair A

The auditor approves questions against exact DESIGNED and IMPLEMENTED revisions, correspondence and assumptions. Dispatch uses this frozen model pair A.

2
Auditor → controller → audit records

Record changed behavior or premise B

New design evidence or auditor clarification revises DESIGNED; code/configuration changes revise IMPLEMENTED. Mark affected correspondence, comparisons, discrepancies and conclusions stale.

3
Worker → controller → audit records

Preserve the earlier evidence

Preserve both earlier models, evidence and discrepancy rationale. A revised design baseline cannot silently erase the original mismatch or rewrite observed implementation.

4
Auditor → controller → auditor

Stop stale acceptance

If the auditor attempts to accept the earlier packet, reject the revision conflict and show the affected premise.

5
Auditor → controller → worker

Authorize revalidation under B

Recompare affected behavior under B at the relevant lenses. The auditor authorizes needed investigation; build current context and dispatch a new attempt.

6
Worker → controller → auditor

Review the current packet

Present current model correspondence, comparison coverage, evidence and remaining gaps. Investigate deviations and design weaknesses; human adjudication controls findings.

Invariant: preserve history; recheck current applicability. Explicit intake and revalidation refresh configuration and fork identity. Reports state observation time and block; v1 does not promise automatic deployment monitoring.
